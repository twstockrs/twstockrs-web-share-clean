# TWStockRS 內部資料匯入格式 v1

這是本專案已實作的標準化匯入格式，供外部資料來源清洗輸出完成後建立明確欄位對照。不是對外部資料來源現有 CSV、Parquet 或資料庫結構的猜測，也不要求先修改外部資料來源清洗程序。第一階段先保存價格及其必要身分／歷史歸屬依賴，後續計算與發布才讀取暫存包。

JSON（文字資料格式）採 UTF-8（中文文字編碼），允許 BOM（檔頭編碼標記）。最外層固定 `format: "TWStockRS-price-import"`、`version: 1`，以及 `manifest`、`securities`、`market_periods`、`calendar`、`sectors`、`memberships`、`prices`。全部欄位必須存在；未知欄位拒絕，不自動轉型、去重、補值或重新命名。空資料表使用 `[]`，空值使用 `null`。

合法與錯誤範例在 `public/samples/import-valid.json`、`public/samples/import-invalid.json`，皆為人造測試，不能視為真實行情。合法範例含轉板、停牌、無成交、ETF（指數股票型基金）及指數。

## 批次說明 manifest

| 欄位 | 型別與規則 |
|---|---|
| batch_id | 1–96 字 ASCII 穩定批次編號；首字為英數，其餘可有 `._:-`。修訂使用新編號 |
| dataset_kind | `test` 人造測試；`source` 來源資料宣告，仍需核對來源真實性 |
| source | 1–120 字非空來源名稱，不含控制字元 |
| source_version | 1–120 字來源版本，與此批輸入對應 |
| created_at | UTC（世界標準時間）ISO 格式，例如 `2026-10-15T00:00:00.000Z`，保留三位毫秒 |
| date_from／date_to | `YYYY-MM-DD`，含起日與迄日；1990–2100 年，每批最多 3661 天 |
| markets | 非空且不重複的 `TWSE`／`TPEx` 陣列 |
| timezone | 固定 `Asia/Taipei` |
| currency | 固定 `TWD`，價格單位為新臺幣，不是千元或其他報價單位 |
| adjustment | 固定包含 method、version、reference_date，明確宣告同批還原方法、版本、基準日期 |

`adjustment.method`、`adjustment.version` 各 1–120 字；`reference_date` 使用合法日期。資料迄日及還原基準日不能晚於 `created_at` 對應的台北日期。這是來源包內部一致性檢查，不代表已獨立驗證供應商、公司行動或交易所日曆。

## 證券身分 securities

| 欄位 | 型別與規則 |
|---|---|
| security_id | 1–96 字穩定身分，格式同 batch_id；不可只由目前代號猜測；表內唯一 |
| code | 字串。股票／ETF 為 4–6 位數字，保留前導零；指數可用 1–32 字英數及 `._:-`，例如 TAIEX |
| name | 1–120 字非空名稱 |
| kind | `stock`／`etf`／`index` |

相同代號的歷史公司可保留不同 security_id，但有效市場期間不能重疊。此表名稱是來源批次的顯示名稱；完整代號／名稱歷史尚待外部資料來源輸出映射及後續正式資料模型，不能用本表回填所有歷史顯示名稱。

## 歷史市場有效期間 market_periods

每列必須有 `segment_id`、`security_id`、`market`、`valid_from`、`valid_to`。segment_id 為唯一穩定市場區段編號，security_id 必須存在，market 必須在批次宣告內。每個證券須至少有一列市場期間。

所有有效期間採 **含起日、不含迄日**，`valid_to: null` 代表尚未結束；有迄日時必須晚於起日。例如 09/15 轉板，舊 TPEx 期間迄日為 09/15，新 TWSE 期間起日為 09/15。價格不能放進舊市場，兩個區段不能重疊。轉板不改 security_id，重新進入同一市場也使用新的 segment_id。下市後原始歷史保留。

## 開休市日曆 calendar

每列有 `market`、`date`、`is_open`；市場及日期為唯一鍵，is_open 是布林值 `true`／`false`。每個宣告市場在 date_from～date_to **每個日曆日都要提供一列**，包括週末與休市日，不根據星期自動猜測開市日。價格列只能出現在該市場 is_open 為 true 的日期。

此層驗證輸入與日曆的一致性。接入外部資料時仍須核對日曆的正式來源與版本；把錯誤日期宣告為開市，不會因結構通過就成為已核准交易日。

## 產業 sectors 與歷史歸屬 memberships

sectors 每列有 `sector_id`、`market`、`name`，sector_id 表內唯一，market 在批次宣告內。名稱 1–120 字，身分格式同 security_id。

memberships 每列有 `security_id`、`sector_id`、`valid_from`、`valid_to`，引用已知 stock 與產業，不能把 ETF／指數當股票成分。有效期間採含起、不含迄，同股的期間不可重疊。批次範圍內股票每個合法開市日期都須有同市場產業歸屬，不以目前產業回填過去；轉板時新舊產業市場也要相符。

只含 ETF／指數的包可使用空 sectors／memberships。此層保存歷史歸屬，不進行等權產業序列運算，也不認證一份來源是否涵蓋完整市場成分。

## 價格與成交狀態 prices

| 欄位 | 型別與規則 |
|---|---|
| security_id／market／date | 已知證券、宣告市場、合法日期；三者合為唯一鍵 |
| status | `traded`、`suspended`、`no_trade`、`unavailable` |
| raw_close | 原始收盤，數字或 null；有成交時須大於 0，最大 10¹² |
| adjusted_close | 同批已宣告方法與版本的還原收盤，數字或 null；有成交時須大於 0，最大 10¹² |
| volume | 股票／ETF 成交股數，安全整數或 null；來源若使用張數須明確換算。指數可為 null |
| reason | null 或 1–240 字原因；合法無新輸入必須提供已確認的原因／來源依據 |

- traded：原始與還原價皆為正數，股票／ETF 成交量為正整數；指數可沒有成交量。
- suspended／no_trade：兩個價格都為 null、成交量為 0、原因非空。來源延用的舊收盤不能當成當天新價格搬入。
- unavailable：容許來源包表達此狀態，但檢查一定未通過，不保存到通過批次；不能偽裝成停牌或補零。

依每個已宣告證券的市場期間與開市日計算應有紀錄，缺列視為來源未完成；新掛牌前及離開市場後不要求價格。批次必須至少有一個應有觀測端點。

此檢查只以**包內宣告的證券集合**判斷缺列，無法辨認整個證券被來源漏掉；整體全市場涵蓋度、官方比較基準對應及來源品質，須在取得外部資料來源實際清單後另核對。還原方法的宣告也不取代實際公司行動與價格數值驗證。

## 大小、保存與報告

網頁檔案上限 8 MiB，還原包裝後 HTTP 請求上限 18 MiB；本機檔案工具上限 512 MiB。MiB 是二進位容量單位，1 MiB＝1,048,576 位元組。每包最多 20,000 證券、100,000 市場期間、100,000 日曆列、10,000 產業、200,000 產業歸屬、3,000,000 價格及應有觀測。較大資料依市場及日期拆包，使用不同批次編號；每包自行攜帶足以驗證的身分與期間依賴，不引用未交付的前批依賴。

日期尋找使用排序後的期間與二分搜尋，避免對每個證券掃描全部日曆及所有歷史期間。512 MiB 是防護上限，不是已完成四年全市場壓力測試的承諾；目前已驗證 104,400 筆價格的檢查及持久保存。正式大檔仍須依實際外部資料來源規模量測，必要時拆批或改為串流輸入。

報告格式 `TWStockRS-import-report` version 1，含檢查時間、批次、資料種類、SHA-256（檔案內容校驗）、ok、錯誤總數、截斷旗標、各表筆數／應有價格筆數，以及 table／row／field／code／message 明細。row 是資料表內從 1 開始的紀錄索引，不是文字檔實體行號；跨列錯誤可為 null。格式早期即不合時，應有筆數可能尚未計算而為 0。網站列前 20 項，報告最多列前 500 項，總數不截斷。

檢查本身不寫資料；確認保存前再次驗證與核對內容校驗。通過批次保存原始 UTF-8 匯入文字、報告與批次索引，單一交易寫入獨立 `imports.sqlite`。同批次編號＋同內容重跑不增加資料；同編號不同內容拒絕覆寫。修訂要新批次編號，既有批次不修改。這一步未建立正式發布版本、啟用指標、RS 運算或資料回復介面。

## 外部資料來源欄位對照待填

拿到一份實際來源樣本與欄位說明後，在下表補入來源檔／欄及轉換規則；禁止先用代號猜穩定身分或使用現在市場回填歷史。

| 內部領域 | 外部資料來源欄位／檔案 | 必須核對 |
|---|---|---|
| security_id／code／kind | 待實際樣本 | 身分穩定、代號重用、ETF／指數類型 |
| 市場區段／生命週期 | 待實際樣本 | 轉板、下市生效日及含起不含迄轉換 |
| 開休市日曆 | 待實際樣本 | 正式來源、範圍、兩市場分開 |
| 原始／還原價 | 待實際樣本 | 價格單位、方法、基準日、版本及公司行動 |
| 成交量／狀態／原因 | 待實際樣本 | 股／張換算；停牌與漏抓的明確區分 |
| 歷史產業歸屬 | 待實際樣本 | 每日有效分類、來源及轉板市場邊界 |
| 來源批次與版本 | 待實際樣本 | 修訂來源、建立時間及可追溯原始檔 |

欄位映射確認後新增適配器（把來源格式明確轉成此格式的程式），以真實邊界樣本驗證。現階段沒有自動掃描外部資料來源檔案、猜欄位或連到另一台電腦。
